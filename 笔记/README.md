## 一、这份笔记怎么用

| 项目 | 说明 |
| :--- | :--- |
| **组织方式** | 一章一个文件夹 → 一节一个 Markdown 文件，与教材目录严格对应 |
| **文件命名** | `章.节 小节标题.md`，例如 `1.4 处理器读并解释储存在内存中的指令.md` |
| **配图来源** | 每节 `images/` 子目录，由 `计算机组成系统图片/` 中的课堂截图复制并重命名而来 |
| **每节结构** | 本节定位 → 核心结论 → 正文（含图）→ 重点速记 → 易错点 → 自测 |
| **建议读法** | 先读「本节定位」和「核心结论」，再看图和正文，最后用「自测」检查 |

> [!TIP]
> 推荐用 **Typora / Obsidian / VS Code（Markdown Preview Enhanced）** 打开，公式与表格渲染最完整；封面式居中排版在 GitHub 上同样可用。

## 四、知识地图（一条主线）

```
hello.c  ——— 编译系统 ———> 可执行文件 hello
   │                            │
   │  第1章：程序的一生          │
   ▼                            ▼
 信息 = 位 + 上下文      进程 / 虚拟内存 / 文件（操作系统抽象）
   │                            │
   │  第2章：位如何解释          │  第1章 1.7
   ▼                            ▼
整数 / 浮点数编码  ──> 第3章：位如何被指令操作（x86-64 汇编、栈、过程调用）
                              │
                              ▼  第4章：指令如何被硬件执行
                     Y86-64 ISA ──> HCL 组合逻辑 ──> 顺序实现 ──> 流水线
```

| 抽象层次 | 本章关注的对象 | 关键问题 |
| :--- | :--- | :--- |
| 应用层 | C 程序 | 我要算什么 |
| 指令集层（ISA） | 汇编 / 机器码 | 硬件"看得懂"哪些动作 |
| 微体系结构层 | 数据通路、控制器 | 一条指令怎样一步步被完成 |
| 逻辑层 | 门电路、HCL | 用与非门搭出加法器和寄存器堆 |

## 五、图片使用说明

1. 笔记中所有插图均为 `计算机组成系统图片/` 内**课堂截图**的副本，按 `章-节_语义名.png` 重命名后放入各章 `images/` 目录，**原图一张不动**。原图共 **147 张**，已**全部用上**（其中 `屏幕截图 2026-10-20 082604.png` 与 `082606.png` 是同一画面存了两次，SHA-256 完全相同，故笔记里只出现一次，实际共 146 个图片文件）。
2. 图注格式统一为 `▲ 图 X-Y-N：说明`，编号规则为「章-节-序号」，按正文出现顺序连续编号（手绘的 `text` 示意图也占一个号）。
3. **没有使用课件 PDF 里的任何插图。**
4. 极少数小节（第 1 章全部、3.1 历史观点、3.11 浮点代码、3.12 小结、2.5 小结）在你的截图库里确实没有对应画面，因此改用表格 + `text` 结构图，并在节末注明"本节无课堂截图"。
5. 原图按 `章-节_语义名` 重命名后复制进笔记，文件名本身已能看出它属于哪一节、画的是什么。
