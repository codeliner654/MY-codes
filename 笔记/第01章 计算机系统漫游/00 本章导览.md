## 一、一条主线：`hello` 的一生

```text
   hello.c                    ┌─────────────┐
  （源程序，文本）  ─────────▶ │  编译系统   │ ─────────▶  hello（可执行文件，二进制）
                              └─────────────┘
                                     │ 预处理 / 编译 / 汇编 / 链接
                                     ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  ① 在 shell 里敲 ./hello                                              │
  │  ② shell 通过系统调用让内核加载 hello（loader）                        │
  │  ③ CPU 从内存取指令、译码、执行，PC 逐条推进                           │
  │  ④ printf 把 "hello, world\n" 交给显示适配器（DMA，绕过 CPU）          │
  └──────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
              这一路上你会依次遇到：编译系统 / 高速缓存 / 存储层次 /
              操作系统抽象（进程·虚拟内存·文件）/ 网络 / 性能与抽象
```

**这一章不追求细节，只追求"位置感"**：后面每一章，都是把这条主线上的某一环放大来看。

## 六、常见误区（先打个预防针）

1. **把"程序"和"进程"混为一谈**：程序是磁盘上的字节，进程是它在内存里的一次运行实例。
2. **以为 CPU 直接读磁盘**：所有 I/O 都要经过总线与 I/O 桥，磁盘数据先进内存。
3. **以为 cache 是"软件缓存"**：这里的 cache 是**硬件**自动管理的 SRAM。
4. **觉得 Amdahl 定律只是公式**：它解释了一个现实——**只优化一小块，整机几乎不变**。
