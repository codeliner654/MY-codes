## 1.10.1 一条主线：`hello` 的一生

把 1.1 到 1.9 首尾相接，就是下面这张图：

```text
  1.1  hello.c 只是一串字节
        │    位 + 上下文；ASCII 只是"恰好"的解释方式
        ▼
  1.2  四个程序把它翻译成 hello
        │    cpp → cc1 → as → ld；.c → .i → .s → .o → hello
        ▼
  1.3  懂编译系统：能优化、能读链接错误、能防缓冲区溢出
        │    strlen 别放循环条件；undefined reference；gets 很危险
        ▼
  1.4  shell 让内核加载它，CPU 开始取指-译码-执行
        │    总线 / I/O 设备 / 主存 / 处理器；DMA 不经过 CPU
        ▼
  1.5  CPU 与主存差约 100 倍，于是有了 cache
        │    L1/L2 命中；靠时间局部性与空间局部性
        ▼
  1.6  存储设备排成层次结构
        │    寄存器 → L1 → L2 → L3 → 主存 → 磁盘 → 网络
        │    上一层是下一层的缓存
        ▼
  1.7  操作系统用三个抽象管理这一切硬件
        │    进程（处理器+主存+I/O）、虚拟内存（主存+磁盘）、文件（I/O）
        ▼
  1.8  网络也只是一种 I/O 设备
        │    hello 可以在服务器上跑，输出传回你的屏幕
        ▼
  1.9  Amdahl 定律 / 并发与并行 / 抽象的重要性
        │
        ▼
  第 2 章：位到底怎样被解释成整数与浮点数
```

*图 1-10-1：全章脉络。注意箭头不是"时间顺序"，而是"抽象层次由低到高再回到应用"。*

## 1.10.2 必须记住的 8 条结论

| # | 结论 | 一句话解释 |
| :-: | :--- | :--- |
| 1 | **信息 = 位 + 上下文** | 同一串字节，按 `int`、`float`、指令解释会得到完全不同的东西 |
| 2 | **程序要经过四道工序** | 预处理 → 编译 → 汇编 → 链接，`.c → .i → .s → .o → hello` |
| 3 | **运行 = 取指-译码-执行** | CPU 沿 PC 逐条走；一切数据搬运都走总线，DMA 是例外（不经 CPU） |
| 4 | **存储是层次的** | 容量↑ 速度↓ 成本↓；上一层是下一层的缓存，靠**局部性**生效 |
| 5 | **操作系统提供三大抽象** | 文件→I/O 设备，虚拟内存→主存+磁盘，进程→处理器+主存+I/O |
| 6 | **网络是 I/O 总线** | 把单机系统扩展成客户端-服务器系统 |
| 7 | **性能有铁律** | Amdahl：$S=1/((1-\alpha)+\alpha/k)$；只优化占比大的部分 |
| 8 | **抽象是驾驭复杂性的唯一办法** | 好的抽象让实现可以随便换，接口保持不变 |

```text
   ①位+上下文   ②四道工序   ③取指译码执行   ④存储层次
        │            │             │              │
        └────────────┴─────────────┴──────────────┘
                             ▼
   ⑤三大抽象（文件/虚拟内存/进程）   ⑥网络 = I/O 总线
                             ▼
   ⑦Amdahl + 局部性 + 并行三层次    ⑧抽象
```

## 1.10.4 名词速查

本章出现的术语，几乎每一个后面都会被展开成一节甚至一章。先把它们钉成一张表：

| 术语 | 英文 | 一句话解释 |
| :--- | :--- | :--- |
| 位 / 字节 | bit / byte | 位是最小信息单位；8 位 = 1 字节，**字节是寻址单位** |
| ASCII | — | 用 1 个字节给字符编号，`#` = `0x23` |
| 预处理器 | cpp | 展开 `#include`、`#define`，产出 `.i` |
| 编译器 | cc1 | 把 C 翻译成汇编，产出 `.s` |
| 汇编器 | as | 把汇编翻译成机器指令，产出 `.o` |
| 链接器 | ld | 符号解析 + 重定位，产出可执行文件 |
| 重定位 | relocation | 把最终地址回填到指令的 4 个字节里 |
| 总线 | bus | 部件之间传送字节的共享电子管道，一次一个字 |
| 主存 | main memory | DRAM 构成的线性字节数组 |
| 程序计数器 | PC / `%rip` | 存下一条要执行指令的地址 |
| 寄存器堆 | register file | 16 个 64 位通用寄存器 |
| ALU | — | 做整数运算与地址计算 |
| DMA | direct memory access | 设备直接读写主存，**不经过 CPU** |
| 高速缓存 | cache | 小而快的暂存区，按 64 字节的块搬运 |
| 局部性 | locality | 时间局部性 + 空间局部性 |
| 内核 | kernel | 常驻内存的管理代码，不是独立进程 |
| 进程 | process | 正在运行的程序，操作系统提供的抽象 |
| 上下文切换 | context switch | 保存旧进程状态、恢复新进程状态 |
| 线程 | thread | 共享地址空间、独享栈与寄存器的执行流 |
| 虚拟内存 | virtual memory | 每个进程私有的、一致的地址空间 |
| 地址翻译 | address translation | 虚拟地址 → 物理地址，由 MMU + 页表完成 |
| 文件 | file | 字节序列，I/O 设备的统一抽象 |
| 超线程 | hyper-threading | 一个核上两套 PC/寄存器，共享执行单元 |
| SIMD | single instruction multiple data | 一条指令同时处理多个数据 |
| Amdahl 定律 | Amdahl's law | 加速比受限于不可加速部分的比例 |

## ⚠️ 易错点

1. **把"这一章只是概述"当成"可以跳过"。** 本章出现的每一个名词（cache、进程、虚拟内存、链接）后面都会用一整章展开，这里建立的是**索引**。
2. **记住流程却记不住"为什么"。** 例如"为什么要分四步编译"——为了复用与可移植，不是为了好看。
3. **把 DMA 说成"CPU 把数据从磁盘搬到内存"。** 正确说法是磁盘控制器直接写主存，CPU 只下命令、收中断。
4. **把 cache 说成"软件缓存"。** 硬件自动管理，程序无感；你能做的只是写出局部性好的代码。
5. **把"虚拟内存"理解成"假的、不存在的内存"。** 它是一套**地址翻译机制**，背后是真实的物理内存 + 磁盘。
6. **用 Amdahl 定律时把 α 取错。** α 是**优化前**该部分占总时间的比例，不是优化后。

## ✅ 自测

1. 用一句话说清 1.2–1.6 这五节各自回答了什么问题。
2. 操作系统提供的三个抽象分别建立在哪些硬件之上？
3. 从 `hello.c` 到屏幕上的 `hello, world`，中间至少经过哪几个"搬运"环节？
4. 如果只能记住本章的一个公式，应该是哪个？为什么？

<details>
<summary>参考答案</summary>

1. 1.2 程序怎样被翻译成可执行文件（四道工序）；1.3 懂编译系统有什么用（性能/链接/安全）；1.4 CPU 怎样读并执行内存中的指令（四部件 + 取指译码执行）；1.5 为什么要 cache（速度差 + 局部性）；1.6 存储设备为什么排成层次（容量/速度/成本）。
2. 文件建立在 I/O 设备之上；虚拟内存建立在主存 + 磁盘之上；进程建立在处理器 + 主存 + I/O 设备之上。
3. 磁盘 →（DMA）主存；主存 → cache → 寄存器（取指/取数）；寄存器 → `printf`/`puts` 处理；字节 → 内核 → 显示适配器 → 显示器。
4. Amdahl 定律 $S=1/((1-\alpha)+\alpha/k)$：它同时给出了"优化哪里"（占比 α）和"能优化到什么程度"（上限 $1/(1-\alpha)$）两个答案，是后续所有性能讨论的出发点。

</details>
