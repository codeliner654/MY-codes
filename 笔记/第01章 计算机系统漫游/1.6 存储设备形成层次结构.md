# 1.6 存储设备形成层次结构

> **📖 本节定位**　第 1 章「计算机系统漫游」· 教材 P9–P10
> **一句话**：把寄存器、cache、主存、磁盘、远程存储按"容量递增、速度递减、成本递减"叠成一座金字塔，**每一层都是下一层的缓存**——这就是整个存储系统的组织原则。

> [!IMPORTANT] 本节要回答的三个问题
> 1. 既然寄存器最快，为什么不把内存全做成寄存器，让所有访问都只要 0.3 ns？
> 2. 上面几层那么小（寄存器 128 B、L1 32 KB），怎么可能"挡住"下面 1 TB 的磁盘？
> 3. "上一层是下一层的缓存"——这句话除了 cache 和主存，还能套在哪些我见过的东西上？

**读之前你需要会**：cache 的"命中 / 不命中"是什么意思（见 [1.5 高速缓存至关重要](1.5%20高速缓存至关重要.md)）、"1 ns = 10⁻⁹ 秒"这种数量级读法。都不会也没关系——本节只用到一个事实：**越快的存储越贵，越贵就只能做小**。

## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | 存储设备不是"平"的，而是**层次结构**：寄存器 → L1 → L2 → L3 → 主存 → 磁盘 → 远程存储 |
| 2 | 三条单调规律：从上到下**容量递增、速度递减、每字节成本递减** |
| 3 | 核心思想只有一句：**上一层的存储器是下一层存储器的高速缓存** |
| 4 | 最顶端的寄存器由**编译器**分配，其余层次由**硬件 + 操作系统**自动管理 |
| 5 | 这个结构之所以成立，是因为程序有**局部性**；没有局部性，金字塔就毫无意义 |
| 6 | 程序员能"看见"的只是虚拟内存这一个平整的假象（下一节 1.7 会解释） |

## 1.6.1 一座金字塔

### 先给一个画面：从口袋到图书馆

**先说它想解决什么问题**：CPU 做一次加法不到 1 ns，可从主存取一个数要 100 ns。如果每次都老老实实等内存，CPU 99% 的时间都在发呆。而"又快又大又便宜"的存储在物理上不存在——快的做不小，大的快不了。唯一的出路是：**把常用的放在手边，不常用的放远处，用一层层"近的"去挡"远的"**。

这个策略你每天都在用，只是没给它起名字：

```text
   口袋        书包         书桌          宿舍书架        图书馆
  128 B      32 KB        256 KB         8 MB           1 TB
  0.3 ns      ~1 ns        ~3 ns         ~15 ns         ~0.1 ms
    │            │            │             │              │
 正在看的     今天要用的   这周要用的    这学期可能用   全部藏书
 那一页       那几本书     那几本参考    的教材          （后备）
```

| 生活里的层 | 对应硬件 | 为什么不干脆换掉它 |
| :--- | :--- | :--- |
| 口袋 | 寄存器 | 只能装一页，但伸手就拿得到 |
| 书包 | L1 / L2 cache | 装不下全部书，但换一本只要一秒 |
| 书桌 | L3 cache | 比书包大，但要站起来去拿 |
| 宿舍书架 | 主存 | 一次能放很多，走两步就到 |
| 图书馆 | 磁盘 / 远程存储 | 什么都有，去一趟要半天 |

> [!TIP]
> 记住这个映射，1.6 剩下的内容就只是"把生活词换成硬件词"：**口袋越小越要勤整理（编译器分配寄存器），图书馆越远越要少去（局部性）**。

教材把从 CPU 内部到网络另一端的存储设备排成一个层次：

```text
                                ┌──────────────┐
                                │    寄存器    │   128 B · 0.3 ns
                                └──────────────┘
                            ┌──────────────────────┐
                            │       L1 cache       │   32 KB · ~1 ns
                            └──────────────────────┘
                        ┌──────────────────────────────┐
                        │           L2 cache           │   256 KB · ~3 ns
                        └──────────────────────────────┘
                    ┌──────────────────────────────────────┐
                    │               L3 cache               │   8 MB · ~15 ns
                    └──────────────────────────────────────┘
                ┌──────────────────────────────────────────────┐
                │                     主存                     │   8 GB · ~100 ns
                └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────────────┐
            │                       本地磁盘                       │   1 TB · ~0.1 ms
            └──────────────────────────────────────────────────────┘
        ┌──────────────────────────────────────────────────────────────┐
        │                       远程存储（网络）                       │   近乎无限 · 更慢
        └──────────────────────────────────────────────────────────────┘
        ◀── 越小 / 越快 / 越贵        越大 / 越慢 / 越便宜 ──▶
```

*图 1-6-1：存储器层次结构。宽度代表容量，高度代表离 CPU 的距离。越靠下越便宜，才能做得越大；越大越慢，于是需要上一层来兜住。*

> [!IMPORTANT]
> 注意这张图**不是"技术栈"，而是"速度与成本的妥协"**。没有哪一层可以被删掉：删掉 cache 则 CPU 空转，删掉磁盘则断电即失，删掉内存则一切都慢到无法忍受。

**形式化定义**：存储器层次结构由若干层组成，第 k 层是第 k+1 层内容的**子集**，并且以**块（block）**为单位搬运。CPU 要的数据在第 k 层就叫**命中（hit）**，直接取用；不在就叫**不命中（miss）**，此时把包含它的整块从第 k+1 层搬上来，必要时**驱逐（evict）**第 k 层的某一块。整座金字塔的性能由**命中率 h** 决定，而不是由任何单独一层的速度决定。

<details>
<summary>✅ 检查点 1：寄存器只有 128 B，为什么程序还能跑得动？</summary>

因为程序**不需要同时**把全部数据放进寄存器。编译器只把"当前这几条指令马上要用"的操作数放进寄存器（16 个 64 位通用寄存器通常够用），其余留在 L1 / 主存。128 B 是"手边"的容量，不是"全部家当"的容量。
</details>

## 1.6.2 三条单调规律

| 层次 | 典型容量 | 访问时间 | 每 GB 成本 | 谁在管理 | 介质 |
| :--- | ---: | ---: | ---: | :--- | :--- |
| 寄存器 | 128 B | 0.3 ns | 极高 | **编译器** | 触发器 |
| L1 cache | 32 KB | ~1 ns | 很高 | 硬件 | SRAM |
| L2 cache | 256 KB | ~3 ns | 高 | 硬件 | SRAM |
| L3 cache | 8 MB | ~15 ns | 较高 | 硬件 | SRAM |
| 主存 | 8 GB | ~100 ns | 中 | 操作系统 | DRAM |
| 本地磁盘 | 1 TB | ~0.1 ms | 低 | 操作系统/文件系统 | 磁/闪存 |
| 远程存储 | 近乎无限 | ~ms 以上 | 最低 | 网络协议/服务 | — |

三条规律从表里一目了然：

```text
   容量   ：  128 B  ──▶  32 KB  ──▶  8 MB  ──▶  8 GB  ──▶  1 TB  ──▶  ∞
   速度   ：  0.3 ns ──▶  ~1 ns  ──▶ ~15 ns ──▶ ~100 ns ─▶ 0.1 ms ──▶ ms+
   成本   ：  最高   ──▶   高    ──▶   中   ──▶   低    ──▶  更低  ──▶ 最低
              （三条方向完全一致，只是符号相反）
```

> [!NOTE]
> 为什么这三条总是同时成立？因为**速度是由物理结构决定的**：越快的存储单元占面积越大、越贵，所以只能做小；而小的东西装不下整个程序，就必须靠下一层来兜底。

<details>
<summary>✅ 检查点 2：把 1 TB 磁盘的容量除以 128 B 寄存器，得到约 86 亿。这个数字想说明什么？</summary>

说明**上一层永远只装得下下一层极小的一部分**（约 $10^{-10}$）。所以层次结构能成立，完全依赖"下一层的访问有局部性"；如果访问真的均匀随机，寄存器 / L1 的命中率会低到接近 0，整座金字塔就退化成磁盘的速度。
</details>

## 1.6.3 核心命题：上一层是下一层的缓存

教材用一句话概括整个结构：

> 存储器层次结构的主要思想是，**上一层的存储器作为低一层存储器的高速缓存**。

把它逐层读一遍：

| 这一层 | 缓存了谁 | 缓存的是什么 |
| :--- | :--- | :--- |
| 寄存器 | L1 | 当前指令正在用的几个操作数 |
| L1 | L2 | 最近访问的指令块与数据块 |
| L2 | L3 / 主存 | 更大范围的最近访问块 |
| 主存 | 磁盘 | 正在运行的程序与它用到的数据（虚拟内存） |
| 磁盘 | 远程存储 | 从网络下载下来的文件、页面（浏览器缓存、NFS） |

```text
      层次 k（小、快、贵）
      ┌───────────────────────────────┐
      │  只装"最近可能用到"的一小部分 │
      └────────────┬──────────────────┘
                   │ 未命中时按"块"向下一层要
                   ▼
      层次 k+1（大、慢、便宜）
      ┌───────────────────────────────┐
      │  装下完整的集合               │
      └───────────────────────────────┘
```

*图 1-6-2：任意相邻两层之间的关系都是"缓存—后备"关系，这套说法对 cache/主存、主存/磁盘、磁盘/网络全都适用。*

> [!TIP]
> 这个观点非常有用：以后看到"虚拟内存把磁盘当内存用""浏览器把网页缓存在本地""CDN 把源站内容放到离用户近的机房"，都可以套进同一个模型——**用一小块快的，挡住一大块慢的**。

#### 一起算一遍

题目：**一次磁盘访问，等于多少次寄存器访问？** 取数量级：寄存器 0.3 ns、L1 1 ns、主存 100 ns、磁盘 10 ms。

| 步骤 | 动作 | 结果 |
| :-: | :--- | :--- |
| ① | 统一单位，全部换成秒 | 寄存器 $3\times10^{-10}$ s；L1 $10^{-9}$ s；主存 $10^{-7}$ s；磁盘 $10^{-2}$ s |
| ② | 磁盘 ÷ 寄存器：$10^{-2} \div (3\times10^{-10})$ | $3.3\times10^{7}$，即 **3333 万次** |
| ③ | 磁盘 ÷ L1：$10^{-2} \div 10^{-9}$ | $10^{7}$，即 **1000 万次** |
| ④ | 磁盘 ÷ 主存：$10^{-2} \div 10^{-7}$ | $10^{5}$，即 **10 万次** |
| ⑤ | 主存 ÷ 寄存器：$10^{-7} \div (3\times10^{-10})$ | 约 **333 次** |
| ⑥ | 换个说法：3 GHz 的 CPU 一个周期约 0.33 ns，磁盘的 10 ms 里能塞多少周期？ | $10^{-2}\div(3.3\times10^{-10})\approx$ **3000 万个周期** |

把第 ② 步换算成人的尺度，冲击力更直接：

```text
   假设一次寄存器访问 = 1 秒
   那么一次 L1 访问   ≈ 3.3 秒
        一次主存访问  ≈ 5.5 分钟
        一次磁盘访问  ≈ 385 天（3.3×10⁷ 秒 ÷ 86400 ≈ 1 年零 3 周）
```

所以"磁盘慢"不是慢一点，是慢**七个数量级**。这也解释了为什么 1.4 节的 DMA 很重要、为什么 1.5 节要引入 cache：**只要一次磁盘访问混进热循环，之前所有的指令级优化都白做了**；反过来，操作系统愿意花很大代价把磁盘内容缓存进主存（虚拟内存），因为省下的一次 10 ms 足以抵消几万次主存访问。

## 1.6.4 为什么整座金字塔能立住

整座金字塔成立的前提只有一个：**程序访问存储器时具有局部性**。

```text
   假设没有局部性（每次访问完全随机）
        │
        ▼
   cache 命中率 ≈ 容量 / 总数据量 ≈ 0
        │
        ▼
   99% 的访问都要走到最慢的那一层
        │
        ▼
   整个层次结构退化成"最慢的那一层"，金字塔白搭
```

反过来，只要命中率足够高，平均访问时间就由"命中的那层"决定：

```text
   T_avg = h × T_快 + (1 − h) × T_慢

   例：h = 0.95，T_快 = 10 周期，T_慢 = 100 周期
   T_avg = 0.95 × 10 + 0.05 × 100 = 9.5 + 5 = 14.5 周期
                                   ↑ 远小于 100
```

| 命中率 h | 平均访问时间（L1=10、主存=100 周期） | 相对"无 cache" |
| ---: | ---: | ---: |
| 0.00 | 100 周期 | 1.0× |
| 0.80 | 28 周期 | 3.6× |
| 0.90 | 19 周期 | 5.3× |
| **0.95** | **14.5 周期** | **6.9×** |
| 0.99 | 10.9 周期 | 9.2× |

<details>
<summary>✅ 检查点 3：命中率 0.95、L1 = 10 周期、主存 = 100 周期，平均访问时间是多少？如果主存变成 200 周期呢？</summary>

第一问：$0.95\times10+0.05\times100=9.5+5=14.5$ 周期。第二问：$0.95\times10+0.05\times200=9.5+10=19.5$ 周期——主存慢一倍，平均只慢 34%，因为 95% 的访问根本没走到主存。这就是"用 cache 挡住慢层"的量化含义。
</details>

> [!WARNING]
> 命中率从 0.95 掉到 0.90，平均时间就从 14.5 涨到 19 周期（慢 31%）。**局部性差一点点，性能就差一大截**——这是第 6 章反复强调的"性能悬崖"。

> [!NOTE] 换个角度想
> 如果当年 SRAM 能做得又大又便宜，"存储器层次结构"这一节可能根本不存在。反过来说，**层次结构不是设计出来的美学，而是被物理成本逼出来的工程妥协**：快的单元面积大 → 单位容量贵 → 只能做小 → 小的装不下程序 → 必须靠慢的兜底。你以后看到任何"多级缓存"（TLB、数据库 buffer pool、DNS 缓存、CDN 边缘节点），结构都长这样，因为约束是同一个。

## 📌 重点速记

```text
层次（上→下）: 寄存器 → L1 → L2 → L3 → 主存 → 本地磁盘 → 远程存储
三条规律     : 容量 ↑、速度 ↓、每字节成本 ↓
核心命题     : 上一层是下一层的缓存
管理者       : 寄存器=编译器；cache=硬件；主存/磁盘=操作系统
介质         : 触发器 / SRAM / SRAM / SRAM / DRAM / 磁盘 / 网络
关键前提     : 局部性（时间 + 空间）
平均访问时间 : T = h·T快 + (1−h)·T慢
典型命中率   : 0.95 时，平均时间约为最慢层的 1/7
```

---

## ⚠️ 易错点

1. **把 L3 也算作"CPU 内部"。** L3 通常在芯片上但被多核共享，容量比 L1/L2 大得多，速度也慢得多——它仍然是"cache"，只是层次更低。
2. **以为寄存器也由硬件自动管理。** 寄存器分配是**编译器**的工作（第 3、5 章），这也是为什么"同一段 C，不同编译器跑出不同速度"。
3. **以为层次越多越好。** 每加一层就多一次判断与搬运开销；实际层次是"命中率提升"与"额外开销"的折中。
4. **以为磁盘"不算存储层次"。** 磁盘是层次结构中的一层（主存的后备），把磁盘纳入进来，才能解释虚拟内存为什么能"比物理内存大"。
5. **把"容量大"当成"性能好"。** 大而慢的层只有在被上层缓存住时才有意义；单看主存 8 GB 并不提升速度。
6. **用算术平均估算性能。** 必须用 `h·T快 + (1−h)·T慢` 这种加权式；未命中的代价是**乘法级**的惩罚。

## ❓ 常见困惑

**Q：L1 只有 32 KB，我的程序有 1 GB，那 99.997% 的数据都不在 cache 里，cache 还有什么用？**
A：程序在任一**时刻**只在一个很小的区域里活动。32 KB 装的是"最近访问过的块"，同一块在两行代码之间可能被复用上亿次。命中率算的是**访问次数**的占比，不是**数据量**的占比——所以 32 KB / 1 GB ≈ 0.003%，命中率照样可以 > 95%。

**Q：为什么寄存器归编译器管，而 cache 归硬件管？**
A：因为寄存器是**指令里写死的名字**（`%rax`、`%rdx`），一条指令用哪个寄存器在机器码里就定死了，硬件无法在运行时替换，只能由编译器在生成代码时分配。cache 则对指令透明——指令只说"访问地址 X"，硬件自己决定从哪一层取。

**Q：既然磁盘这么慢，为什么不全用内存？**
A：三条硬约束：容量（1 TB vs 8 GB）、成本（每 GB 差两个数量级）、**断电后 DRAM 内容会丢**（需要不断刷新）。磁盘/闪存"大、便宜、持久"这三点恰好是内存给不了的，所以它必须留在最下面当后备。

**Q：命中率 95% 和 99% 看着差不多，为什么书里说差很多？**
A：要看"未命中的代价放大多少倍"。按 L1 = 10、主存 = 100 周期算，95% → 14.5 周期，99% → 10.9 周期，差 33%；如果未命中要走磁盘（10 ms），两者的差距会变成 20 倍。**命中率的分量，由未命中的代价决定。**

## 🛠 动手试试

1. 量一量真机的 cache 与页大小：

   ```bash
   getconf -a | grep -Ei 'CACHE_SIZE|PAGESIZE'
   ```

   预期：能看到 `LEVEL1_DCACHE_SIZE 32768`（32 KB）、`LEVEL2_CACHE_SIZE 262144`（256 KB）、`LEVEL3_CACHE_SIZE` 几 MB 这样的行——和本节表格里的量级对得上。

2. 用 `perf` 看一次真实的命中与不命中：

   ```bash
   perf stat -e cycles,instructions,cache-references,cache-misses ./a.out
   ```

   预期：`cache-misses` 通常只占 `cache-references` 的百分之几。把数组访问从顺序改成随机跳着走，再跑一次，`cache-misses` 的比例会明显上升。

3. 亲手验证"顺序访问比随机访问快"：开一个 64 MB 的 `int` 数组，先顺序累加，再按 `(i*16777619) % N` 跳着累加，各跑三次取平均。

   预期：顺序版明显更快（常见 2–5 倍）。因为顺序访问把整块 64 B 都利用上了（空间局部性），随机版几乎每次都在等一个新的 cache 块。

5. 命中率从 0.99 降到 0.90，平均访问时间变化多少（L1=10、主存=100 周期）？

<details>
<summary>参考答案</summary>

1. 寄存器 → L1 cache → L2 cache → L3 cache → 主存 → 本地磁盘 → 远程存储。
2. 容量递增、访问速度递减、每字节成本递减。因为速度由物理结构决定：越快的单元越占面积、越贵，只能做小；做小了装不下全部数据，就必须用更慢更大的下一层兜底。
3. 正在运行的程序和数据从磁盘被"调页"进主存；主存里保存的是磁盘内容的一小部分高频子集，磁盘才是完整的后备存储。所以主存是磁盘的缓存。
4. 寄存器由**编译器**在生成代码时分配（软件管理）；cache、主存、磁盘由硬件与操作系统自动管理（对程序透明）。
5. 0.99 时约 `0.99×10 + 0.01×100 = 10.9` 周期；0.90 时约 `19` 周期，慢了约 74%。

</details>
