# 1.6 存储设备形成层次结构

> **📖 本节定位**　第 1 章「计算机系统漫游」· 教材 P9–P10
> **一句话**：把寄存器、cache、主存、磁盘、远程存储按"容量递增、速度递减、成本递减"叠成一座金字塔，**每一层都是下一层的缓存**——这就是整个存储系统的组织原则。

[← 上一节：1.5 高速缓存至关重要](1.5%20高速缓存至关重要.md)　｜　[下一节：1.7 操作系统管理硬件 →](1.7%20操作系统管理硬件.md)

---

## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | 存储设备不是"平"的，而是**层次结构**：寄存器 → L1 → L2 → L3 → 主存 → 磁盘 → 远程存储 |
| 2 | 三条单调规律：从上到下**容量递增、速度递减、每字节成本递减** |
| 3 | 核心思想只有一句：**上一层的存储器是下一层存储器的高速缓存** |
| 4 | 最顶端的寄存器由**编译器**分配，其余层次由**硬件 + 操作系统**自动管理 |
| 5 | 这个结构之所以成立，是因为程序有**局部性**；没有局部性，金字塔就毫无意义 |
| 6 | 程序员能"看见"的只是虚拟内存这一个平整的假象（下一节 1.7 会解释） |

---

## 1.6.1 一座金字塔

教材把从 CPU 内部到网络另一端的存储设备排成一个层次：

```text
                                ┌──────────────┐
                                │    寄存器    │   128 B · 0.3 ns
                                └──────────────┘
                            ┌──────────────────────┐
                            │       L1 cache       │   32 KB · ~1 ns
                            └──────────────────────┘
                        ┌──────────────────────────────┐
                        │           L2 cache           │   256 KB · ~3 ns
                        └──────────────────────────────┘
                    ┌──────────────────────────────────────┐
                    │               L3 cache               │   8 MB · ~15 ns
                    └──────────────────────────────────────┘
                ┌──────────────────────────────────────────────┐
                │                     主存                     │   8 GB · ~100 ns
                └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────────────┐
            │                       本地磁盘                       │   1 TB · ~0.1 ms
            └──────────────────────────────────────────────────────┘
        ┌──────────────────────────────────────────────────────────────┐
        │                       远程存储（网络）                       │   近乎无限 · 更慢
        └──────────────────────────────────────────────────────────────┘
        ◀── 越小 / 越快 / 越贵        越大 / 越慢 / 越便宜 ──▶
```

*图 1-6-1：存储器层次结构。宽度代表容量，高度代表离 CPU 的距离。越靠下越便宜，才能做得越大；越大越慢，于是需要上一层来兜住。*

> [!IMPORTANT]
> 注意这张图**不是"技术栈"，而是"速度与成本的妥协"**。没有哪一层可以被删掉：删掉 cache 则 CPU 空转，删掉磁盘则断电即失，删掉内存则一切都慢到无法忍受。

---

## 1.6.2 三条单调规律

| 层次 | 典型容量 | 访问时间 | 每 GB 成本 | 谁在管理 | 介质 |
| :--- | ---: | ---: | ---: | :--- | :--- |
| 寄存器 | 128 B | 0.3 ns | 极高 | **编译器** | 触发器 |
| L1 cache | 32 KB | ~1 ns | 很高 | 硬件 | SRAM |
| L2 cache | 256 KB | ~3 ns | 高 | 硬件 | SRAM |
| L3 cache | 8 MB | ~15 ns | 较高 | 硬件 | SRAM |
| 主存 | 8 GB | ~100 ns | 中 | 操作系统 | DRAM |
| 本地磁盘 | 1 TB | ~0.1 ms | 低 | 操作系统/文件系统 | 磁/闪存 |
| 远程存储 | 近乎无限 | ~ms 以上 | 最低 | 网络协议/服务 | — |

三条规律从表里一目了然：

```text
   容量   ：  128 B  ──▶  32 KB  ──▶  8 MB  ──▶  8 GB  ──▶  1 TB  ──▶  ∞
   速度   ：  0.3 ns ──▶  ~1 ns  ──▶ ~15 ns ──▶ ~100 ns ─▶ 0.1 ms ──▶ ms+
   成本   ：  最高   ──▶   高    ──▶   中   ──▶   低    ──▶  更低  ──▶ 最低
              （三条方向完全一致，只是符号相反）
```

> [!NOTE]
> 为什么这三条总是同时成立？因为**速度是由物理结构决定的**：越快的存储单元占面积越大、越贵，所以只能做小；而小的东西装不下整个程序，就必须靠下一层来兜底。

---

## 1.6.3 核心命题：上一层是下一层的缓存

教材用一句话概括整个结构：

> 存储器层次结构的主要思想是，**上一层的存储器作为低一层存储器的高速缓存**。

把它逐层读一遍：

| 这一层 | 缓存了谁 | 缓存的是什么 |
| :--- | :--- | :--- |
| 寄存器 | L1 | 当前指令正在用的几个操作数 |
| L1 | L2 | 最近访问的指令块与数据块 |
| L2 | L3 / 主存 | 更大范围的最近访问块 |
| 主存 | 磁盘 | 正在运行的程序与它用到的数据（虚拟内存） |
| 磁盘 | 远程存储 | 从网络下载下来的文件、页面（浏览器缓存、NFS） |

```text
      层次 k（小、快、贵）
      ┌───────────────────────────────┐
      │  只装"最近可能用到"的一小部分 │
      └────────────┬──────────────────┘
                   │ 未命中时按"块"向下一层要
                   ▼
      层次 k+1（大、慢、便宜）
      ┌───────────────────────────────┐
      │  装下完整的集合               │
      └───────────────────────────────┘
```

*图 1-6-2：任意相邻两层之间的关系都是"缓存—后备"关系，这套说法对 cache/主存、主存/磁盘、磁盘/网络全都适用。*

> [!TIP]
> 这个观点非常有用：以后看到"虚拟内存把磁盘当内存用""浏览器把网页缓存在本地""CDN 把源站内容放到离用户近的机房"，都可以套进同一个模型——**用一小块快的，挡住一大块慢的**。

## 1.6.4 为什么整座金字塔能立住

整座金字塔成立的前提只有一个：**程序访问存储器时具有局部性**。

```text
   假设没有局部性（每次访问完全随机）
        │
        ▼
   cache 命中率 ≈ 容量 / 总数据量 ≈ 0
        │
        ▼
   99% 的访问都要走到最慢的那一层
        │
        ▼
   整个层次结构退化成"最慢的那一层"，金字塔白搭
```

反过来，只要命中率足够高，平均访问时间就由"命中的那层"决定：

```text
   T_avg = h × T_快 + (1 − h) × T_慢

   例：h = 0.95，T_快 = 10 周期，T_慢 = 100 周期
   T_avg = 0.95 × 10 + 0.05 × 100 = 9.5 + 5 = 14.5 周期
                                   ↑ 远小于 100
```

| 命中率 h | 平均访问时间（L1=10、主存=100 周期） | 相对"无 cache" |
| ---: | ---: | ---: |
| 0.00 | 100 周期 | 1.0× |
| 0.80 | 28 周期 | 3.6× |
| 0.90 | 19 周期 | 5.3× |
| **0.95** | **14.5 周期** | **6.9×** |
| 0.99 | 10.9 周期 | 9.2× |

> [!WARNING]
> 命中率从 0.95 掉到 0.90，平均时间就从 14.5 涨到 19 周期（慢 31%）。**局部性差一点点，性能就差一大截**——这是第 6 章反复强调的"性能悬崖"。

## 📌 重点速记

```text
层次（上→下）: 寄存器 → L1 → L2 → L3 → 主存 → 本地磁盘 → 远程存储
三条规律     : 容量 ↑、速度 ↓、每字节成本 ↓
核心命题     : 上一层是下一层的缓存
管理者       : 寄存器=编译器；cache=硬件；主存/磁盘=操作系统
介质         : 触发器 / SRAM / SRAM / SRAM / DRAM / 磁盘 / 网络
关键前提     : 局部性（时间 + 空间）
平均访问时间 : T = h·T快 + (1−h)·T慢
典型命中率   : 0.95 时，平均时间约为最慢层的 1/7
```

---

## ⚠️ 易错点

1. **把 L3 也算作"CPU 内部"。** L3 通常在芯片上但被多核共享，容量比 L1/L2 大得多，速度也慢得多——它仍然是"cache"，只是层次更低。
2. **以为寄存器也由硬件自动管理。** 寄存器分配是**编译器**的工作（第 3、5 章），这也是为什么"同一段 C，不同编译器跑出不同速度"。
3. **以为层次越多越好。** 每加一层就多一次判断与搬运开销；实际层次是"命中率提升"与"额外开销"的折中。
4. **以为磁盘"不算存储层次"。** 磁盘是层次结构中的一层（主存的后备），把磁盘纳入进来，才能解释虚拟内存为什么能"比物理内存大"。
5. **把"容量大"当成"性能好"。** 大而慢的层只有在被上层缓存住时才有意义；单看主存 8 GB 并不提升速度。
6. **用算术平均估算性能。** 必须用 `h·T快 + (1−h)·T慢` 这种加权式；未命中的代价是**乘法级**的惩罚。

## ✅ 自测

1. 按从快到慢的顺序写出存储器层次结构（至少 6 层）。
2. 三条单调规律分别是什么？为什么它们能同时成立？
3. "上一层的存储器是下一层的缓存"这句话，对"主存—磁盘"这一对怎么解释？
4. 寄存器和其他层次在"管理者"上有什么不同？
5. 命中率从 0.99 降到 0.90，平均访问时间变化多少（L1=10、主存=100 周期）？

<details>
<summary>参考答案</summary>

1. 寄存器 → L1 cache → L2 cache → L3 cache → 主存 → 本地磁盘 → 远程存储。
2. 容量递增、访问速度递减、每字节成本递减。因为速度由物理结构决定：越快的单元越占面积、越贵，只能做小；做小了装不下全部数据，就必须用更慢更大的下一层兜底。
3. 正在运行的程序和数据从磁盘被"调页"进主存；主存里保存的是磁盘内容的一小部分高频子集，磁盘才是完整的后备存储。所以主存是磁盘的缓存。
4. 寄存器由**编译器**在生成代码时分配（软件管理）；cache、主存、磁盘由硬件与操作系统自动管理（对程序透明）。
5. 0.99 时约 `0.99×10 + 0.01×100 = 10.9` 周期；0.90 时约 `19` 周期，慢了约 74%。

</details>
