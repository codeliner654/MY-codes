# 1.8 系统之间利用网络通信

> **📖 本节定位**　第 1 章「计算机系统漫游」· 教材 P14–P16
> **一句话**：把网卡插进 I/O 总线，一台机器就能读写另一台机器的内存——**网络只是又一种 I/O 设备**，于是 `hello` 可以在一台机器上敲、在另一台机器上跑。

## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | 对主机而言，**网络就是一种 I/O 总线**：网卡插在 I/O 总线上，和磁盘控制器地位相同 |
| 2 | 网络的作用是**把信息从一台主机复制到另一台主机** |
| 3 | 典型路径：主机 → 以太网适配器 → 局域网 → 路由器 → 广域网 → 路由器 → 局域网 → 目标主机 |
| 4 | `ssh`/`telnet` 远程运行程序时，**输入、输出走网络，计算发生在服务器上** |
| 5 | 这套协作叫**客户端-服务器模型**：客户端发起请求，服务器提供服务 |
| 6 | 网络把"单机系统"扩展成"分布式系统"，也为第 11、12 章（网络编程、并发服务器）埋下伏笔 |

## 1.8.1 网络就是一种 I/O 总线

回忆 1.4 节的硬件图：CPU 通过**系统总线**连到**I/O 总线**，再连到各种适配器。以太网适配器（网卡）就插在这条 I/O 总线上。

```text
   CPU ── 系统总线 ── I/O 总线 ──┬── 磁盘控制器
                                 ├── 显示适配器
                                 └── 以太网适配器 ── 网线 ──▶ 另一台机器
                                          ▲
                       从 CPU 的角度看，网卡和磁盘控制器没有本质区别：
                       都是"往某个地址写一串字节，然后等它完成"
```

*图 1-8-1：网络被"降格"成了一种 I/O 设备。这正是本节标题"系统之间利用网络通信"的技术基础。*

| 对比项 | 磁盘 | 网络 |
| :--- | :--- | :--- |
| 连接方式 | 磁盘控制器插在 I/O 总线 | 以太网适配器插在 I/O 总线 |
| CPU 如何操作 | 写寄存器、读寄存器 | 写寄存器、读寄存器 |
| 数据单位 | 扇区 / 文件块 | 数据包（packet / frame） |
| 传输方向 | 到本地存储介质 | 到另一台主机 |

> [!IMPORTANT]
> 教材的原话是：**对主机而言，网络只是一种 I/O 设备。** 一旦接受这个观点，"远程登录"就不再神秘——它只是"从另一台机器的内存里读写字节"。

但这种 I/O 的代价比磁盘还大，量级要对清楚：

| 访问对象 | 典型延迟 | 说明 |
| :--- | ---: | :--- |
| L1 cache | ~1 ns | 对照用 |
| 主存 | ~100 ns | 对照用 |
| 同机房的另一台机器 | ~0.05–0.5 ms | 一次往返（RTT） |
| 跨城 | ~10–30 ms | 光速 + 路由跳数 |
| 跨洲 | ~100–200 ms | 光纤中光速约 20 万 km/s |

> [!TIP]
> 一次跨洲往返的时间里，CPU 能执行上千万条指令。所以高性能服务器的一条铁律是**少说话**：把多次小请求合并成一次大请求，省下的时间远超任何代码优化。

## 1.8.2 一台机器怎样连到另一台

从你的笔记本到机房里的服务器，中间通常要过这么几道关：

四段链路，三次转发：

```text
   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
   │ 笔记本 │──▶│ 路由器 │──▶│ 路由器 │──▶│ 服务器 │
   └────────┘   └────────┘   └────────┘   └────────┘
     局域网         广域网         局域网
```

*图 1-8-2：一次跨网络的通信要穿过"适配器—局域网—路由器—广域网—路由器—局域网—适配器"。*

> [!NOTE]
> 教材只画了"以太网段 + 路由器 + 广域网"三层。真实网络还有交换机、NAT、防火墙、CDN，但对"数据怎么从 A 到 B"这个问题，教材的简化模型已经够用。

## 1.8.3 远程运行 hello：五步数据流

假设你在客户端敲：

```bash
ssh user@server          # 或 telnet server（不安全，已淘汰）
server$ ./hello
hello, world
```

这短短几行，背后是两台机器的完整协作：

| 步 | 发生在哪 | 做了什么 |
| :-: | :--- | :--- |
| ① | 客户端 | 键盘输入的字符进入客户端内存，`ssh` 把它们打包 |
| ② | 客户端 → 服务器 | 数据包经网卡 → 局域网 → 路由器 → 广域网 → 服务器网卡 |
| ③ | 服务器内核 | 拆包，把字节交给 `sshd`；`sshd` 启动一个 shell |
| ④ | 服务器 | shell 执行 `./hello`，加载器把程序装入内存，CPU 开始跑 |
| ⑤ | 服务器 → 客户端 | `hello, world\n` 原路返回，显示在客户端屏幕上 |

```text
   ┌──────────────────────────────┐         ┌──────────────────────────────┐
   │ 客户端（你）                 │         │ 服务器（远端）               │
   │ 键盘 → 内存 → ssh 进程       │══网络══ │ sshd → shell → ./hello       │
   │ 以太网适配器                 │         │ 以太网适配器                 │
   └──────────────────────────────┘         └──────────────────────────────┘
     ▶─── 输入（按键、命令）───────────────────────
     ◀─── 输出（hello, world 原路返回）───────
```

*图 1-8-3：计算结果全部在服务器上产生，客户端只负责"送输入、接输出"。*

> [!WARNING]
> 不要以为"远程运行"是客户端在跑程序。**程序在服务器上执行**，客户端只是一个"远程终端"。你在本地看到的每个字符，都是网络另一头送过来的。

要找到"另一台机器上的那个服务"，靠的是三样东西：

| 约定 | 作用 | 例子 |
| :--- | :--- | :--- |
| IP 地址 | 定位**哪一台机器** | `192.168.1.20` |
| 端口号 | 定位机器上的**哪一个服务** | SSH 默认 22，HTTP 默认 80 |
| 传输协议 | 规定字节怎么编号、怎么应答 | TCP 保证可靠、有序 |

> [!NOTE]
> 地址 + 端口 + 协议，合起来就是一个"套接字（socket）"。第 11 章会从 `socket()` 这个系统调用开始，亲手写一个客户端和服务器。

## 1.8.4 客户端-服务器模型

这种协作方式有一个通用名字：**客户端-服务器模型（client-server model）**。

| 角色 | 职责 | 例子 |
| :--- | :--- | :--- |
| **客户端** | 发起请求、展示结果 | 你的浏览器、`ssh`、`ftp` |
| **服务器** | 等待请求、提供服务、返回结果 | Web 服务器、数据库、`sshd` |

```text
   客户端 A ──┐
   客户端 B ──┼──▶  服务器（一个进程服务多个客户端）
   客户端 C ──┘
```

这个模型有三个要点：

1. **服务器是被动的**：它不主动找人，只等请求；
2. **一对多**：一台服务器可以同时服务成百上千个客户端（第 12 章讲怎么做到）；
3. **位置无关**：客户端不需要知道服务器在哪，只要知道"地址 + 端口"。

把 1.7 的抽象拿来对照：**进程**让一台机器同时跑多个程序，**网络**让多台机器协同跑一个程序。第 11、12 章会把这两件事合起来——并发服务器。

## 📌 重点速记

```text
网络地位 : 一种 I/O 总线，网卡插在 I/O 总线上
网络作用 : 把信息从一台主机复制到另一台主机
典型路径 : 主机→适配器→局域网→路由器→广域网→路由器→局域网→适配器→主机
远程执行 : 输入/输出走网络，计算发生在服务器
五步流程 : 键盘→打包→传输→服务器执行→结果回传
模型     : 客户端-服务器（请求 / 响应，一对多）
类比     : 进程=单机并发；网络=多机协同
```

## ⚠️ 易错点

1. **以为"网络是特殊的硬件"。** 对 CPU 而言它和磁盘控制器一样，只是 I/O 总线上的一个设备。
2. **以为远程运行时"程序在本地跑，只是显示在远端"。** 恰恰相反：程序在服务器上跑，本地只是终端。
3. **把"局域网"和"广域网"混为一谈。** 局域网（LAN）覆盖小范围、延迟低；广域网（WAN）跨地域，靠路由器互联。
4. **以为路由器"转发"的是整个文件。** 它转发的是**数据包**，一个文件会被切成很多包分别传输。
5. **以为 SSH 和 telnet 只是名字不同。** telnet 明文传输（密码可被嗅探），SSH 加密；现在只用 SSH。

## ✅ 自测

1. 为什么说"网络是一种 I/O 总线"？从 CPU 的角度看，网卡和磁盘控制器有什么共同点？
2. 写出一台主机到另一台主机的典型网络路径（至少 5 个环节）。
3. 用 `ssh` 远程运行 `hello` 时，程序到底在哪台机器上执行？客户端负责什么？
4. 客户端-服务器模型的两个角色各做什么？为什么说服务器是"被动"的？
5. 远程执行时，`hello` 的输出经过哪些环节才显示在你的屏幕上？

<details>
<summary>参考答案</summary>

1. 因为网卡（以太网适配器）插在 I/O 总线上，CPU 通过读写它的寄存器来收发数据，与操作磁盘控制器的方式没有本质区别；两者都是"往设备写数据、等它完成"。
2. 客户端主机 → 以太网适配器 → 局域网 → 路由器 → 广域网 → 路由器 → 局域网 → 以太网适配器 → 服务器主机。
3. 程序在**服务器**上执行；客户端只负责把键盘输入打包发出去，并把返回的字节显示在屏幕上。
4. 客户端发起请求并展示结果；服务器等待请求、处理并返回结果。因为服务器不主动发起通信，只在收到请求后才响应。
5. `hello` 把字节写到服务器进程的 stdout → 内核 → `sshd` 打包 → 服务器网卡 → 网络 → 客户端网卡 → 客户端 `ssh` 进程 → 客户端内核 → 显示适配器 → 屏幕。

</details>
