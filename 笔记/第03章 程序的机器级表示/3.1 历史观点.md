# 3.1 历史观点

> **📖 本节定位**　第 3 章「程序的机器级表示」· 教材 P110–113
> **一句话**：x86 今天所有"别扭"的地方——通用寄存器只有 16 个、指令长度从 1 字节到 15 字节、寻址方式一大堆——都不是设计出来的，而是 40 多年**向后兼容**一层层叠出来的。

## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | x86 的 "x" 来自 **8086/8088**，"86" 是型号后缀；这一族从 16 位一路兼容到 64 位，从未推倒重来 |
| 2 | 时间轴：**1978 8086（16 位）→ 1985 i386（32 位，IA32）→ 2008 Core i7（x86-64）**，每一步都保留旧指令 |
| 3 | x86-64 并非 Intel 首创，是 **AMD 2003 年**在 Opteron 上提出的 AMD64，Intel 随后以 EM64T 跟进 |
| 4 | 向后兼容的代价是**编码格式被 1978 年的设计锁死**：寄存器字段只有 3 位、指令必须变长、寻址模式只能加不能减 |
| 5 | x86 是典型的 **CISC**：变长指令、内存可直接当运算操作数、寄存器少；RISC 则定长、load/store、寄存器多 |
| 6 | 现代 x86 处理器内部早已 **RISC 化**：前端把 x86 指令翻译成定长微指令（µop），后端按 RISC 方式乱序执行 |

## 3.1.1 从 8086 到 Core i7：一条不断加长的谱系

教材用一句话概括这段历史：**Intel 的处理器系列统称 x86，因为最早的处理器型号是 8086，而后续型号都以 86 结尾**（80286、i386、i486 …）。这条谱系的关键节点如下：

| 年份 | 处理器 | 位宽 | 关键变化 |
| :--- | :--- | :-: | :--- |
| 1978 | **8086** | 16 | x86 起点：8 个 16 位通用寄存器；20 位地址（段:偏移）→ 1 MB 空间 |
| 1980 | 8087 | — | 浮点协处理器，x87 指令集；`flds`/`fldl` 的 `s`/`l` 后缀由此而来（见 3.3） |
| 1982 | 80286 | 16 | 保护模式，24 位地址 → 16 MB |
| 1985 | **i386** | 32 | **IA32 起点**：平坦 32 位地址空间 → 4 GB；寄存器整体扩到 32 位 |
| 1989 | i486 | 32 | 浮点部件与片上 cache 集成进 CPU |
| 1993 | Pentium | 32 | 双路超标量（superscalar），一个周期可发射两条指令 |
| 1995 | Pentium Pro | 32 | **P6 微架构**：乱序执行、寄存器重命名、推测执行，今天 x86 后端的祖宗 |
| 1997–99 | Pentium II / III | 32 | MMX、**SSE**：`%xmm` 向量寄存器登场 |
| 2000 | Pentium 4 | 32 | Netburst：超长流水线、拼高主频；2004 年 Prescott 起才支持 Intel 64 |
| 2003 | AMD Opteron | 64 | **AMD64（即 x86-64）**：寄存器扩到 16 个、指针 8 字节 |
| 2006 | Core 2 | 64 | 放弃 Netburst、回到 P6 血统；双核 / 四核普及 |
| 2008 | **Core i7**（Nehalem） | 64 | 4 核 8 线程、集成内存控制器、SSE4.2；后续 Sandy Bridge 引入 AVX |

把它画成一条时间线，可以清楚看到"位宽每 10–20 年翻一倍，但旧代码一直能跑"：

```text
  1978       1982       1985       1993       1995       2000       2006       2008
    │          │          │          │          │          │          │          │
┌───┴───┐  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐
│ 8086  │  │ 80286 │  │ i386  │  │Pentium│  │Pentium│  │  P4   │  │Core 2 │  │Core i7│
│ 16bit │  │ 16bit │  │ IA32  │  │ 32bit │  │Pro P6 │  │ 32bit │  │ 64bit │  │  x64  │
└───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘
    │          │          │          │          │          │          │          │
    └────────────────────────────────────────────────────────────────────────────┘
              ←────  40 年只做加法，从不删指令  ────→
```

> [!NOTE]
> 这张图只画了 Intel 主线。**64 位那一档不是 Intel 先开的**：2003 年 AMD 的 Opteron（K8）先推出 AMD64，Intel 直到 2004 年的 Prescott 才以 EM64T 跟进，两家最终统一到同一套 x86-64。所以今天说"x86-64"，指的是 AMD 定义、Intel 兼容的那套 64 位扩展。
>
> 另外，"位宽"这一列要分开看：8086 的**寄存器**是 16 位，地址却是 20 位（用 `段寄存器 << 4 + 偏移` 凑出来）；Core 2 之后的"64 位"指 **x86-64 模式**下寄存器与指针都是 64 位。教材关注的是**程序员可见的位宽**，而不是引脚数。

## 3.1.2 向后兼容：一个不能反悔的承诺

x86 家族最重要的设计约束只有一条：

> **新的处理器必须能正确执行旧处理器编译出的任何二进制代码。**

```text
   1978 年编出的 8086 机器码                   2019 年的 Core i9
   ┌──────────────────────┐                  ┌──────────────────────┐
   │  53                  │  ──────────────▶ │ 解码器仍然认识 0x53  │
   │  （push bx，1 字节） │                  │ → 译成 push %rbx     │
   └──────────────────────┘                  └──────────────────────┘
```

`0x53` 这个字节在 1978 年表示 `push %bx`，在今天的 x86-64 上表示 `push %rbx`——**同一个字节，含义被"长大"了，但绝不能被改成别的指令**。3.2 节 `objdump` 里那行 `0: 53  push %rbx`，就是这段历史活生生的证据。

### 兼容性留下的五个"历史包袱"

下表前三条是教材点名要求的，后两条属于"考古但仍在影响今天"的部分：

| 历史包袱 | 由来 | 今天的代价 / 补救 |
| :--- | :--- | :--- |
| **通用寄存器只有 16 个** | 1978 年指令编码里寄存器字段只有 **3 位**（2³ = 8 个） | x86-64 靠 **REX 前缀**把字段扩到 4 位才凑出 16 个；RISC-V 直接给 32 个。寄存器不够，编译器只能把变量 **spill 到栈上** |
| **指令变长（1–15 字节）** | 新指令不能挤占旧编码，只能靠"加前缀"塞进去（`0x66` 改操作数大小、`0x67` 改地址大小、`0x40–0x4F` 是 REX、`VEX` 再套一层） | 取指时**必须先串行确定这条指令有多长**，无法像定长指令那样一次切好几条，前端成为瓶颈；现代 CPU 用 µop cache + 预解码部分绕开 |
| **寻址模式复杂** | 1978 年为了方便访问数组和结构体：基址 + 变址×比例 + 位移 | 解码器和地址生成单元（AGU）复杂；好处是 `leaq 8(%rdi,%rsi,4), %rax` 一条指令就能算 `rdi + rsi*4 + 8` |
| **条件码隐式依赖** | 8086 的 FLAGS 寄存器，指令执行完"顺手"改标志位 | 指令有隐藏的读写依赖，乱序执行必须额外做标志位重命名 |
| **段式内存** | 8086 只有 16 位寄存器，靠"段 × 16 + 偏移"才能寻 1 MB | 现代 OS 把段基址全设为 0，只留 `%fs` / `%gs` 给线程局部存储（TLS） |

> [!IMPORTANT]
> **兼容 ≠ 免费。** 上面每一条"包袱"背后都是真金白银的电路和性能：x86 的取指解码前端比同工艺的 ARM 复杂得多，靠巨大的后端乱序执行引擎才把性能拉回来。教材让你理解历史，正是为了让你在看到"为什么寄存器这么少""为什么指令长短不一"时不去钻牛角尖。

> [!TIP]
> 考试里常问"为什么 x86-64 只有 16 个通用寄存器，而 RISC-V 有 32 个？"标准答法是：**x86-64 的寄存器编号嵌在 1978 年的指令编码里，只有 3 位，AMD 只能加一个 REX 前缀把它扩成 4 位（16 个）**；而 RISC-V 是全新设计的 ISA，字段宽度可以随便定，5 位就能编 32 个。

## 3.1.3 CISC 与 RISC

按"指令集复杂程度"划分，两大流派的核心差异如下：

| 维度 | **CISC**（x86-64） | **RISC**（ARM64 / RISC-V） |
| :--- | :--- | :--- |
| 指令长度 | **变长**，1–15 字节，平均约 3 字节 | **定长**，4 字节 |
| 指令条数 | 上千条（含大量历史遗留） | 几十到几百条，正交、精简 |
| 寻址模式 | 十几种，内存可直接做 `add` 的操作数 | 只有 **load/store** 访存，运算只在寄存器间进行 |
| 通用寄存器 | 16 个 | 32 个 |
| 条件码 | 独立 FLAGS，指令**隐式**修改 | 多为比较后显式分支（ARM 可选 `s` 后缀） |
| 流水线友好度 | 差：变长指令难以并行取指 | 好：定长、字段位置固定，译码简单 |
| 代码密度 | 高（常用指令只有 1–2 字节） | 低（每条固定 4 字节） |
| 编译器负担 | 大（要挑指令、挑寻址方式） | 小（指令规整，调度容易） |
| 典型代表 | 8086 至今的全部 x86 | ARM64、RISC-V、MIPS、PowerPC |

但"界限"早就不那么清楚了：

```text
        x86 指令流（变长、复杂、CISC）
              │
              ▼
      ┌───────────────┐   译码    ┌────────────────────────────┐
      │ 预取 + 解码   │ ────────▶ │ µop：微指令，类 RISC、定长 │
      └───────────────┘           └─────────────┬──────────────┘
                                                ▼
                              乱序调度 / 寄存器重命名 / 多个执行单元
                                        （RISC 式后端）
```

> [!WARNING]
> **不要用"CISC 落后、RISC 先进"来答题。** 现代 x86 是"CISC 外壳 + RISC 内核"：对外保持变长编码以兼容旧程序、压缩代码体积，对内翻译成 µop 后按 RISC 方式流水。反过来，ARM 也在不断加复杂指令（如 SIMD 的 `sdot`）。ISA 的"主义"之争，今天更多是**生态与编码效率**的权衡。

## ⚠️ 易错点

1. **把"机器字长 64 位"和"字 = 16 位"混为一谈。** x86-64 的**字长**（指针宽度）是 64 位；而 3.3 节数据格式里的 **Word 仍是 2 字节**。两个"字"不是一回事。
2. **以为 x86-64 是 Intel 发明的。** 是 **AMD 2003 年**在 Opteron 上先做出来的（AMD64），Intel 后来才跟进；所以 64 位这套扩展的正式名字叫 **AMD64**，`gcc` 的 64 位目标三元组里也写着 `x86_64`。
3. **以为"向后兼容"只是软件问题。** 它是**硬件编码层面**的约束：新指令必须找到还没被占用的字节序列，于是才有 `0x66`/`0x67`/REX/VEX 这些前缀层层叠加。
4. **以为 8086 是 20 位寄存器。** 8086 的寄存器全是 **16 位**，1 MB 地址空间是靠 `段寄存器 × 16 + 偏移` 算出来的，不是寄存器变宽了。
5. **以为 CISC 的复杂指令一定更慢。** 单条复杂指令可能占用多个 µop，但**代码更短**、取指次数更少，某些场景反而占优。
6. **把 IA32 和 x86-64 的 `long` / 指针混着记。** IA32 下 `long` 和指针都是 **4 字节**，x86-64 下都是 **8 字节**——这正是 3.3 要建立的表格。

## ✅ 自测

1. 8086、i386、Core i7 分别是哪一年推出的？各自程序员可见的位宽是多少？
2. x86-64 是谁先提出的？Intel 为什么必须跟进？
3. 写出 x86 "向后兼容"造成的三个历史包袱，并各说明它对性能的一处影响。
4. 为什么 x86-64 只有 16 个通用寄存器，而不是 32 个？这与指令编码有什么关系？
5. 用一句话解释"x86 是 CISC 外壳、RISC 内核"。

<details>
<summary>参考答案</summary>

1. 8086：1978 年，16 位；i386：1985 年，32 位（IA32）；Core i7：2008 年，64 位（x86-64）。
2. AMD 于 2003 年在 Opteron 上提出 AMD64。Intel 必须跟进，否则用户无法在 Intel 芯片上运行 64 位新软件，生态会被 AMD 抢走；Intel 的实现叫 EM64T / Intel 64，指令集与 AMD64 基本一致。
3. ① 寄存器只有 16 个（编码字段 3 位）→ 编译器频繁 spill，访存增多；② 指令 1–15 字节变长 → 取指要先串行定长，前端吞吐受限；③ 条件码隐式依赖 → 指令间有隐藏依赖，乱序执行需额外重命名。（也可答：复杂寻址模式 → 解码与 AGU 复杂；段式内存 → 需硬件兼容。）
4. 因为寄存器编号嵌在 1978 年的 ModR/M 字节里，只有 3 位。x86-64 用 REX 前缀的 1 位把它扩到 4 位，恰好 16 个；要再扩就得再加前缀，代价过高。
5. 对外仍是变长、复杂的 x86 指令（兼容旧程序、压缩代码体积），但 CPU 前端把它译成定长 µop，后端按乱序、多发射的 RISC 方式执行。

</details>
