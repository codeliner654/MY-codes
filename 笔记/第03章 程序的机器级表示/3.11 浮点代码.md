## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | 浮点寄存器是 **`%xmm0`–`%xmm15`**（各 128 位）；标量单精度用低 32 位、双精度用低 64 位，传送靠 `movss`（4 字节）/ `movsd`（8 字节） |
| 2 | **不能**把浮点常数当立即数写进指令，只能存在内存里（`.long` 对或 `.quad`），用 RIP 相对寻址加载 |
| 3 | 转换指令的名字就是方向：`ss2sd` 单→双、`sd2ss` 双→单、`si2sd` 整→浮点、`sd2si` 浮点→整；带 `t` 的是**截断** |
| 4 | 浮点参数用 `%xmm0`–`%xmm7`，返回值用 `%xmm0`；整数与浮点**各用各的寄存器、各自计数** |
| 5 | 算术指令是三操作数：`vaddsd %xmm1, %xmm2, %xmm0` 表示 `%xmm0 = %xmm2 + %xmm1`（源在前、目的在最后） |
| 6 | 比较用 `ucomisd`/`ucomiss`，置 `ZF/PF/CF`；**`PF=1` 即"有 NaN"**，所以只能用 `seta`/`setae` |

## 3.11.1 浮点传送和转换

x86-64 有 16 个 **XMM 寄存器** `%xmm0`–`%xmm15`，每个 128 位，原本为 SSE 向量指令设计；标量浮点只用其中一小段：

```text
  %xmm0  127                                                                0
        ┌───────────────────────────────────────────────────────────────┐
        │                       128 位（16 字节）                       │
        └───────────────────────────────────────────────────────────────┘
          单精度 float 只用低 32 位  ──┬──
          双精度 double 只用低 64 位 ──┼──────────
```

*▲ 图 3-11-1：一条 `movss` 只动低 32 位、`movsd` 只动低 64 位；正因为"按需取用低位"，同一组寄存器既能算 `float` 也能算 `double`。*

| 指令 | 源 → 目的 | 宽度 | 说明 |
| :--- | :--- | :-: | :--- |
| `vmovss` | M32 / XMM → XMM | 4 | 单精度 |
| `vmovsd` | M64 / XMM → XMM | 8 | 双精度 |
| `vmovaps`/`vmovapd`、`vmovups`/`vmovupd` | XMM ↔ M128 | 16 | 整块传送（对齐版不对齐会异常） |

```asm
    vmovss  (%rdi), %xmm0          # 从内存读一个 float
    vmovsd  (%rsi,%rcx,8), %xmm2   # double 数组取元素：比例因子 8
```

**转换指令的方向写在名字里**：`cvt` + 源类型 + `2` + 目的类型（`ss` 单精度、`sd` 双精度、`si` 有符号整数）：

| 指令 | 方向 | 语义 |
| :--- | :--- | :--- |
| `vcvtss2sd` | 单 → 双 | 精确（单精度一定能被双精度表示） |
| `vcvtsd2ss` | 双 → 单 | **可能舍入**（按 MXCSR 的舍入模式） |
| `vcvtsi2ss` / `vcvtsi2sd` | 整 → 浮点 | 源可以是 32 位或 64 位整数 |
| `vcvtss2si` / `vcvtsd2si` | 浮点 → 整 | 按**当前舍入模式**取整 |
| `vcvttss2si` / `vcvttsd2si` | 浮点 → 整 | 带 `tt` = **截断**（向零取整） |

```asm
    vcvtsi2sdl  %edi, %xmm0, %xmm0     # (double)i    其中 i 是 int
    vcvtsi2sdq  %rdi, %xmm1, %xmm1     # (double)l    其中 l 是 long（q 后缀 = 64 位源）
    vcvtsd2ss   %xmm1, %xmm2, %xmm2    # (float)d
    vcvttsd2si  %xmm2, %eax            # (int)d       截断：3.9 → 3，-3.9 → -3
```

> [!WARNING]
> `(int)` 强转在 C 里是"向零取整"，所以编译器必须用 `cvtt…`（截断）版本。误用 `cvtsd2si` 会按**当前舍入模式**（默认四舍五入）取整：`(int)3.9` 变成 4，与 C 语义不符。

## 3.11.2 过程中的浮点代码

SysV x86-64 为浮点单独开了一套参数寄存器：

| 用途 | 寄存器 | 说明 |
| :--- | :--- | :--- |
| 浮点参数 1–8 | `%xmm0` – `%xmm7` | 与整数参数**独立编号** |
| 浮点返回值 | `%xmm0` | 单精度/双精度都用它 |
| 整数参数 | `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9` | 与 XMM 互不干扰 |
| 调用者保存 | **所有** `%xmm` | SysV 没有"被调用者保存"的 XMM |

```c
double f(int a, double b, int c, double d);
/* a → %edi  b → %xmm0  c → %esi  d → %xmm1：两条互不干扰的传送带 */
```

```c
double funct(double a, float x, int b, int c) { return a * x + b - c; }
```

```asm
# a 在 %xmm0，x 在 %xmm1，b 在 %edi，c 在 %esi
funct:
    vcvtss2sd %xmm1, %xmm1, %xmm1   # x = (double)x        ← 单精度先升到双精度
    vmulsd    %xmm0, %xmm1, %xmm1   # a*x
    vcvtsi2sd %edi, %xmm2, %xmm2    # (double)b
    vaddsd    %xmm2, %xmm1, %xmm1   # a*x + b
    vcvtsi2sd %esi, %xmm3, %xmm3    # (double)c
    vsubsd    %xmm3, %xmm1, %xmm0   # (a*x + b) - c  → 返回值放 %xmm0
    ret
```

三点值得注意：`float` 参数进来后**先转 `double`**（C 的算术在"比 int 高的类型"里做）；**整数参数必须显式转**（`vcvtsi2sd`），这就是混合类型表达式在机器级的真实代价；**返回值必须在 `%xmm0`**，所以最后一条 `vsubsd` 的目的操作数就是它。

## 3.11.3 浮点运算操作

| 运算 | 双精度 | 单精度 | AT&T 三操作数语义 |
| :--- | :--- | :--- | :--- |
| 加 | `vaddsd` | `vaddss` | `vaddsd %xmm1, %xmm2, %xmm0` → `xmm0 = xmm2 + xmm1` |
| 减 | `vsubsd` | `vsubss` | `vsubsd %xmm1, %xmm2, %xmm0` → `xmm0 = xmm2 - xmm1` |
| 乘 | `vmulsd` | `vmulss` | `vmulsd %xmm1, %xmm2, %xmm0` → `xmm0 = xmm2 * xmm1` |
| 除 | `vdivsd` | `vdivss` | `vdivsd %xmm1, %xmm2, %xmm0` → `xmm0 = xmm2 / xmm1` |

**操作数顺序是最容易错的地方**：AT&T 把"目的"写在最后，三操作数形式里**第一个操作数是第二个源**：

```text
   vsubsd   %xmm1,  %xmm2,  %xmm0
             │        │        └─ 目的：xmm0
             │        └────────── 第一源（被减数）
             └─────────────────── 第二源（减数）
   结果： xmm0 = xmm2 - xmm1        ← 不是 xmm1 - xmm2 ！
```

*▲ 图 3-11-2：四则运算里只有减法和除法不满足交换律，所以这个顺序必须背死。*

第一源可以是内存操作数（第二源不行）：`vmulsd .LC0(%rip), %xmm0, %xmm0` 就是"乘以内存里的常数"；`vaddsd (%rdi,%rsi,8), %xmm0, %xmm0` 是"加上 `A[i]`"。

## 3.11.4 定义和使用浮点常数

x86-64 **没有浮点立即数**：指令编码里放不下一个 64 位 IEEE 754 常量。所以浮点常数必须**存在内存里**，再用 RIP 相对寻址读进来。

```c
double cel2fahr(double temp) { return 1.8 * temp + 32.0; }
```

```asm
# temp 在 %xmm0
cel2fahr:
    vmulsd  .LC2(%rip), %xmm0, %xmm0    # temp * 1.8
    vaddsd  .LC3(%rip), %xmm0, %xmm0    # + 32.0
    ret

    .section .rodata
.LC2:                                   # double 1.8 = 0x3FFC CCCCCCCCCCCD
    .long   3435973837                  # 低 4 字节 0xCCCCCCCD
    .long   1073532108                  # 高 4 字节 0x3FFCCCCC
.LC3:                                   # double 32.0 = 0x4040 000000000000
    .long   0                           # 低 4 字节 0x00000000
    .long   1077936128                  # 高 4 字节 0x40400000
```

```text
   1.8 的 IEEE 754 双精度位模式：
   ┌─┬───────────┬────────────────────────────────────────────────────┐
   │0│ 011 1111  │ 1100 1100 1100 1100 1100 1100 1100 1100 1100 1101  │
   │ │ 1111 1100 │                     (尾数 52 位)                   │
   └─┴───────────┴────────────────────────────────────────────────────┘
    符号  阶码 0x3FF                尾数 0xCCCCCCCCCCCCD
   高 32 位 = 0x3FFCCCCC = 1073532108     低 32 位 = 0xCCCCCCCD = 3435973837
```

*▲ 图 3-11-3：教材把 `1.8` 拆成两个 `.long`，按**小端**顺序"低 4 字节在前"存放；拼回去正好是 `0x3FFCCCCCCCCCCCCD`。*

| 写法 | 例子 | 特点 |
| :--- | :--- | :--- |
| 两个 `.long` | `.long 3435973837` / `.long 1073532108` | gcc 实际输出；**依赖小端**，可读性差 |
| 一个 `.quad` | `.quad 4607182418800017408`（= 1.0 的 `0x3FF0000000000000`） | 一句搞定，不依赖字内字节序 |

> [!TIP]
> 需要"浮点零"时不用麻烦内存：`vxorpd %xmm0, %xmm0, %xmm0` 一条指令就得到 `+0.0`，而且 CPU 对"寄存器自己异或自己"有特殊优化（零延迟、不占执行单元）。这也是编译器清零 XMM 的标准手法。

## 3.11.5 浮点位级操作

SSE 提供了一组**按位**作用于 XMM 的指令：它们不看 IEEE 754 的含义，只做布尔运算（名字里的 `ps`/`pd` 只是"按 4 个单精度"/"按 2 个双精度"切分）：

| 指令 | 运算 | 常见用途 |
| :--- | :--- | :--- |
| `vandps` / `vandpd` | 按位与 | 清符号位（取绝对值）、取指数字段 |
| `vorps` / `vorpd` | 按位或 | 置位、拼装位域 |
| `vxorps` / `vxorpd` | 按位异或 | 清零、翻转符号位（取负） |

**取绝对值 = 清掉符号位；取负 = 翻转符号位**：

```asm
    vandpd  .LC0(%rip), %xmm0, %xmm0     # x & 0x7FFF…  → |x|
    vxorpd  .LC1(%rip), %xmm0, %xmm0     # x ^ 0x8000…  → -x
.LC0:
    .quad   0x7FFFFFFFFFFFFFFF           # 除符号位全 1
.LC1:
    .quad   0x8000000000000000           # 只有符号位
```

```text
   x        = 1 10000000000 100100…      （-3.25）
   mask     = 0 11111111111 111111…      （0x7FFF…）
   ─────────────────────────────────
   x & mask = 0 10000000000 100100…      （+3.25，绝对值）

   x        = 0 10000000000 100100…      （+3.25）
   x ^ mask = 1 10000000000 100100…      （-3.25，取负，mask = 0x8000…）
```

*▲ 图 3-11-4：浮点"取负"根本不用算术单元，只翻一个 bit；这也解释了为什么 `-0.0` 与 `+0.0` 数值相等但位模式不同。*

对 `float` 用 `vandps` 时掩码是低 4 字节的 `0x7FFFFFFF`；对 `double` 用 `vandpd` 时是低 8 字节的 `0x7FFFFFFFFFFFFFFF`。按 128 位整体运算时高半部分也会被与掉——只要不把高半部分当数据用就无害。

## 3.11.6 浮点比较操作

浮点比较不能用 `cmp`（那是整数指令），要用 `ucomisd`/`ucomiss`：

```asm
    vucomisd %xmm1, %xmm0      # AT&T：目的在最后 → 比较 %xmm0 与 %xmm1
```

结果不写寄存器，只置**三个条件码** `ZF`、`PF`、`CF`（`OF`、`SF`、`AF` 被清零）：

| 关系（`%xmm0` 相对 `%xmm1`） | CF | ZF | PF |
| :--- | :-: | :-: | :-: |
| 大于 | 0 | 0 | 0 |
| 小于 | 1 | 0 | 0 |
| 等于 | 0 | 1 | 0 |
| **无序（有 NaN）** | **1** | **1** | **1** |

**`PF=1` 就是"无序"的标志**：只要任一操作数是 NaN，三个标志同时为 1。后果是：`setb`（CF=1）与 `setbe`（CF=1 或 ZF=1）在 NaN 时会**误判为真**，不能用；只有 `seta`（CF=0 且 ZF=0）与 `setae`（CF=0）在 NaN 时为假，符合 C 的"NaN 参与比较一律为假"。

所以 gcc 会**交换操作数**，让"小于"也变成"大于"来判断：

```asm
# int lt(double a, double b) { return a < b; }   a 在 %xmm0，b 在 %xmm1
lt:
    vucomisd %xmm0, %xmm1      # ← 变成"比较 b 与 a"（操作数交换）
    seta     %al               # b > a 即 a < b；无序时 CF=1 → seta 为假 ✔
    movzbl   %al, %eax
    ret
# a <= b 同理，只把 seta 换成 setae；a > b / a >= b 则不交换，直接 seta / setae
```

**"等于"最麻烦**，因为无序时 `ZF` 也是 1，必须再确认"有序"：

```asm
# int eq(double a, double b) { return a == b; }
    vucomisd %xmm1, %xmm0
    sete     %al               # ZF=1：可能是"相等"，也可能是 NaN
    setnp    %dl               # PF=0：确认"有序"
    andl     %edx, %eax        # 两者都为真才算"相等"
```

> [!IMPORTANT]
> **浮点比较与整数比较的条件码互不通用**：整数看 `SF`/`OF`（`setl`、`setg`、`setle`、`setge`），浮点看 `CF`/`ZF`/`PF`（`seta`、`setae`、`setb`、`setbe`、`sete`）。在浮点比较后面写 `setl`，得到的是完全无意义的结果——这是读反汇编时的高频错误。

## 3.11.7 观察结论

| 观察 | 具体表现 |
| :--- | :--- |
| **结构相似** | 同样是"寄存器 + 内存操作数"，同样比较之后接跳转，同样由编译器做寄存器分配与循环优化 |
| **指令集不同** | 不同的寄存器文件（XMM vs GPR）、不同的助记符、不同的参数寄存器与返回值寄存器 |
| **`-Og`** | 生成的都是标量 `…ss`/`…sd` 指令，一条只算一个数，与源码一一对应，便于调试 |
| **`-O2`** | 循环展开、把标量合并成向量（`vaddpd`、`vmulpd`），甚至融合成 FMA（`vfmadd132sd`），汇编与源码的对应关系被打散 |
| **`long double`** | 用 **x87** 的 80 位扩展精度：`fld`/`fstp`、`%st(0)`–`%st(7)` 这组**寄存器栈**，参数只能走内存，比 SSE 慢很多 |

```text
   同一段 C 代码，两套后端：
   C:  sum += a[i] * b[i];

   ── 标量（-Og，SSE）──            ── 向量（-O2，AVX）──
   vmovss (a,i,4), %xmm0             vmovups (%rdi), %ymm0
   vmulss (b,i,4), %xmm0             vmulps  (%rsi), %ymm0, %ymm0
   vaddss %xmm0, %xmm1               vaddps  %ymm0, %ymm1, %ymm1
   每次 1 个 float                    每次 8 个 float
```

*▲ 图 3-11-5：指令集是"数据宽度 + 语义"的组合；理解了 `…ss/…sd` 的标量形式，向量形式只是把同样的动作一次做 4/8 份。*

> [!TIP]
> 复习时把"浮点指令"当成整数指令的**影子副本**来记：`movq`↔`movsd`、`addq`↔`addsd`、`cmpq`↔`ucomisd`、`cvttsd2si`↔`movslq`（都是"换表示"）。一条一条对上，记忆量立刻减半。

```text
           vsubsd %xmm1,%xmm2,%xmm0  ==  xmm0 = xmm2 - xmm1

```

## ⚠️ 易错点

1. **`vsubsd %xmm1, %xmm2, %xmm0` 读成 `xmm1 - xmm2`**。正确是 `xmm2 - xmm1`（目的在最后，第一源是倒数第二个操作数）。
2. **把 `movsd` 当成"移动 4 字节"**。`movss` 才是 4 字节单精度；`movsd` 是 8 字节双精度（`s` 是 scalar，`s/d` 才是 single/double）。
3. **以为 `(int)d` 用 `cvtsd2si`**。C 的强转是截断，必须用 `cvttsd2si`；否则 `(int)2.9` 会得到 3。
4. **浮点比较后用 `setl`/`setg`**。浮点比较只置 `CF/ZF/PF`，`setl` 依据的是 `SF≠OF`，结果毫无意义。
5. **以为 NaN 会让 `a <= b` 为真**。无序时 `CF=ZF=1`，`setbe` 会误判；必须交换操作数改用 `setae`，`==` 时还要补 `setnp`。
6. **给浮点指令写立即数**：`movsd $1.0, %xmm0` 汇编直接报错，常数必须放内存；也别忘了浮点参数与整数参数**各自从 1 开始编位**（`f(int a, double b, int c, double d)` 里 `b` 是 `%xmm0`、`d` 才是 `%xmm1`）。

## ✅ 自测

1. 写出把 `%edi` 里的 `int` 转成 `double` 放进 `%xmm0` 的指令；再写出把 `%xmm1` 里的 `double` 截断成 `int` 放进 `%eax` 的指令。
2. `double f(int a, double b, int c, double d, double e)` 的五个参数分别放在哪个寄存器？
3. `vsubsd %xmm3, %xmm2, %xmm1` 计算的是什么？若想算 `xmm3 - xmm2` 该写什么？
4. 为什么 `ucomisd` 之后判断"小于等于"要用 `setae` 而不是 `setbe`？`1.0` 的位模式用 `.quad` 写出来是十进制几？

<details>
<summary>参考答案</summary>

1. `vcvtsi2sdl %edi, %xmm0, %xmm0`；`vcvttsd2si %xmm1, %eax`。
2. `a→%edi`、`b→%xmm0`、`c→%esi`、`d→%xmm1`、`e→%xmm2`（整数与浮点各自从 1 开始数）。
3. 算 `%xmm1 = %xmm2 - %xmm3`；要算 `%xmm3 - %xmm2` 应写 `vsubsd %xmm2, %xmm3, %xmm1`。
4. NaN 参与比较时 `CF=1`、`ZF=1`，`setbe`（CF=1 或 ZF=1）会返回真，与 C 语义相反；`setae` 只看 `CF=0`，配合交换操作数正好等于"小于等于"。`1.0` 是 `0x3FF0000000000000`，即 `4607182418800017408`。

</details>
