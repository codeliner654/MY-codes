## 🎯 核心结论

| # | 结论 |
| :-: | :--- |
| 1 | 机器级程序只有三种基本动作：**把字节搬来搬去、做整数/浮点算术、按条件跳转** |
| 2 | 一切 C 构造都被编译器翻译成"地址计算 + 访存 + 条件码 + 跳转"的组合 |
| 3 | 寄存器是**有限的公共资源**：通用寄存器 16 个、XMM 16 个，谁被破坏由 ABI 规定 |
| 4 | 栈是"过程调用"的载体：参数、返回地址、保存的寄存器、局部变量都在栈帧里 |
| 5 | 数组/结构只是地址算术；过程的边界由 `call`/`ret` 与栈帧约定划出 |
| 6 | 理解了机器级，才看得懂缓冲区溢出、性能优化（第 5 章）与处理器实现（第 4 章） |

### C 构造 → 汇编骨架

| C 构造 | 汇编骨架（`-Og`） | 关键点 |
| :--- | :--- | :--- |
| `if (a > b) X else Y` | `cmp` → `jle .Lelse` → X → `jmp .Lend` → `.Lelse:` Y | 条件取反，跳到"不成立"分支 |
| `while (i < n)` | `.Lloop:` `cmp` → `jge .Ldone` → 体 → `jmp .Lloop` | 循环体尾部的 `jmp` 可省略为往回跳 |
| `for (i=0; i<n; i++)` | 同 `while`，`i++` 放在体之后 | `-O2` 会做循环展开 |
| `switch (x)` | `cmp $max, %eax` → `ja .Ldefault` → `jmp *.Ltab(,%rax,8)` | 跳转表（`.quad` 数组） |
| `a[i]` | `movl (%rdi,%rsi,4), %eax` | 基址 + 变址 × 比例因子 |
| `s->f` | `movl 8(%rdi), %eax` | 基址 + 常量偏移 |
| `f(x, y)` | `movq %rsi, %rdi` 等 → `call f` | 参数搬进 `%rdi…`，返回值读 `%rax` |
| `p = malloc(n)` | `call malloc` → 检查 `%rax` 是否为 0 | 返回值 16 字节对齐 |

> [!IMPORTANT]
> AT&T 语法的**操作数顺序与 Intel 相反**：`movq %rsi, %rdi` 是"把 `%rsi` 的值送进 `%rdi`"（源在前、目的在后）。读任何一段 CSAPP 汇编，先把这条规则刻进脑子，后面 90% 的误读都会消失。

## 3.12.2 x86-64 指令速查总表

| 类别 | 指令 | 典型形式 | 说明 |
| :--- | :--- | :--- | :--- |
| 传送 | `mov{b,w,l,q}` | `movq %rsi, %rdi` | 搬字节，宽度看后缀 |
| 传送 | `movabsq` | `movabsq $imm64, %rax` | 64 位立即数 |
| 扩展 | `movz{bw,bl,wl,…}` | `movzbl (%rdi), %eax` | 零扩展（常用于无符号） |
| 扩展 | `movs{bw,bl,wl,sl,…}` | `movslq %eax, %rax` | 符号扩展（下标常用） |
| 栈 | `pushq` / `popq` | `pushq %rbp` | `%rsp` 先减/后加 8，再存/取 |
| 地址 | `leaq` | `leaq 8(%rdi,%rsi,4), %rax` | **只算地址，不访存** |
| 算术 | `add` / `sub` | `addq %rsi, %rdi` | 置条件码 |
| 算术 | `imul` | `imulq %rsi, %rdi` / `imulq $3, %rsi, %rax` | 有符号乘；两/三操作数 |
| 算术 | `idivq` / `divq` | `idivq %rcx` | 被除数在 `%rdx:%rax` |
| 算术 | `neg` / `inc` / `dec` | `negq %rax` | 取负 / 加一 / 减一 |
| 逻辑 | `and` / `or` / `xor` / `not` | `xorq %rax, %rax` | 清零常用 `xor` |
| 移位 | `sal`/`shl`、`sar`、`shr` | `salq $6, %rdx` | 左移、算术右移、逻辑右移 |
| 比较 | `cmp` / `test` | `cmpq %rsi, %rdi` / `testq %rax, %rax` | 只置标志，不写结果 |
| 跳转 | `jmp` / `jCC` | `je`、`jne`、`jg`、`jle`、`ja`、`jb` | 有符号用 `g/l`，无符号用 `a/b` |
| 置位 | `setCC` | `setl %al`、`seta %al` | 把条件码变成 0/1 字节 |
| 传送 | `cmovCC` | `cmovne %rsi, %rdi` | 条件传送，避免分支预测失败 |
| 过程 | `call` / `ret` | `call 0x400520 <add>` | 压/弹返回地址（`%rip`） |
| 过程 | `leave` | `leave` | `movq %rbp,%rsp` + `popq %rbp` |
| 浮点传送 | `movss` / `movsd` | `movsd (%rdi), %xmm0` | 4 / 8 字节 |
| 浮点算术 | `addsd`…`divsd`（`ss` 单精度） | `vaddsd %xmm1, %xmm2, %xmm0` | 三操作数，源在前 |
| 浮点转换 | `cvtsi2sd` / `cvttsd2si` | `vcvttsd2si %xmm1, %eax` | `tt` = 截断 |
| 浮点比较 | `ucomisd` / `ucomiss` | `ucomisd %xmm1, %xmm0` | 置 `ZF/PF/CF` |
| 浮点位运算 | `andpd` / `xorpd` | `vandpd .LC0(%rip), %xmm0, %xmm0` | 清/翻符号位 |

> [!TIP]
> 记指令只需记三件事：**操作几个字节（后缀）、操作数在哪（寄存器/内存/立即数）、有没有副作用（是否置条件码）**。其余细节查表即可。

## 3.12.3 寄存器分工速查

| 寄存器 | 约定用途 | 谁负责保存 |
| :--- | :--- | :--- |
| `%rax` | 返回值；`idivq` 的商 | 调用者 |
| `%rdx` | 第 3 个参数；`idivq` 的余数 | 调用者 |
| `%rsp` | 栈指针 | 由 `call/ret/push/pop` 维护 |
| `%rbp` | 帧指针（可选） | 被调用者 |
| `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9` | 整数参数 1–6 | 调用者 |
| `%rbx`、`%r12`–`%r15` | 长期保存的局部变量 | **被调用者** |
| `%r10`、`%r11` | 临时 | 调用者 |
| `%xmm0`–`%xmm7` | 浮点参数 / 返回值（`%xmm0`） | 调用者（全部） |

**一次调用发生时的栈**（`caller` 调用 `callee(1, 2.0)`）：

```text
   高地址
  ┌──────────────────────────┐
  │  caller 的栈帧           │
  ├──────────────────────────┤
  │  传入的第 7 个及以后参数   │ ← 寄存器不够用时才上栈
  ├──────────────────────────┤
  │  返回地址（call 压入）     │ ← %rsp 在 call 之后指向这里
  ├──────────────────────────┤
  │  保存的 %rbp（callee 压）  │ ← callee 的 pushq %rbp
  ├──────────────────────────┤
  │  callee 的局部变量 / VLA   │ ← subq $N, %rsp
  └──────────────────────────┘
   低地址                       ← %rsp 全程指向"当前栈顶"
```

*▲ 图 3-12-2：`%rsp` 从高地址往低地址长；返回地址夹在两层栈帧之间，正是 3.10.3 缓冲区溢出要改写的那一格。*

> [!WARNING]
> `%rbp` 在固定栈帧里**可以省掉**（`-fomit-frame-pointer`），此时"帧"只靠 `%rsp` 维护。读优化过的汇编时，不要假设一定能看到 `push %rbp / mov %rsp,%rbp` 这一对序言。

## 3.12.4 必记的 10 条结论

1. **一切皆字节**：内存是字节数组，地址是下标；类型只在编译期起作用。
2. **宽度看后缀**：`movb/movw/movl/movq` = 1/2/4/8 字节；写 32 位寄存器会清零高 32 位。
3. **`leaq` 是算术指令**：只算地址不访存，`leaq (%rdi,%rsi,4)` 就是 `rdi + 4*rsi`。
4. **条件码是控制的枢纽**：`cmp`/`test`/`sub`/`add` 置 `ZF/SF/CF/OF`，`jCC`/`setCC`/`cmovCC` 消费它们。
5. **有符号与无符号靠不同的 `jCC`/`setCC` 区分**：`g/l` 看 `SF`/`OF`，`a/b` 看 `CF`/`ZF`。
6. **过程三件事**：参数（6 个整数 + 8 个浮点）、返回地址、栈帧；`call` 与 `ret` 自动操作 `%rip`。
7. **寄存器谁来救**：`%rbx`、`%rbp`、`%r12–%r15` 被调用者保存；其余（含全部 XMM）调用者保存。
8. **数组/结构是地址算术**：`&E[i] = E + i*sizeof(T)`；结构体成员是"基址 + 常量偏移"，偏移受对齐约束。
9. **缓冲区溢出的本质是"数据写到了返回地址上"**；防线是栈随机化、canary、NX、ASLR，但根本办法是检查长度。
10. **浮点是另一套世界**：`%xmm0–15`、`…ss/…sd` 指令、`ucomisd` 比较；结构相似而指令集不同。

## 📌 重点速记

```text
三种动作 : 搬字节（mov） / 算（add,imul,sal,leaq） / 跳（cmp+jCC）
后缀     : b=1 w=2 l=4 q=8；写 32 位清零高 32 位
寻址     : D(Rb,Ri,S) = Rb + Ri*S + D，S ∈ {1,2,4,8}
条件码   : ZF 零 / SF 符号 / CF 进位(无符号借位) / OF 溢出(有符号)
有符号   : jg jge jl jle  cmovg  setl
无符号   : ja jae jb jbe  cmova  setb
过程     : 参数 rdi rsi rdx rcx r8 r9 / xmm0-7；返回 rax / xmm0
栈帧     : push rbp; mov rsp,rbp; sub $N,rsp … leave; ret
数组     : &E[i]=E+i*sizeof(T)；int A[R][C] → A+4*(C*i+j)
结构     : 成员固定偏移 + 对齐填充；union 偏移全 0
浮点     : movsd / addsd / ucomisd / cvttsd2si；常数只能放内存
```

## ⚠️ 易错点

1. **把"汇编"当成"难"**。它只是没有语法糖的 C：`for` 变 `cmp+jmp`，`a[i]` 变 `(%rdi,%rsi,4)`，其余全是同一套逻辑。
2. **忽略后缀**。把 `movl` 写成 `movq`（或反之）会读到相邻内存或只写一半。
3. **`cmpq %rsi, %rdi` 的方向**。AT&T 里是"`%rdi - %rsi`"，所以 `jg` 表示 `%rdi > %rsi`。
4. **以为 `%rax` 只存返回值**。它同时是 `idivq` 的被除数低半、`imul` 的默认目的，读汇编时要看上下文。
5. **以为栈是从小地址向大地址增长**。x86-64 的栈**向低地址增长**：`push` 先减 `%rsp` 再写。
6. **忘记"被调用者保存"的责任**。在被调函数里改了 `%rbx` 却没恢复，调用者的变量会莫名改变。
7. **把"对齐填充"当成编译器 bug**。`sizeof` 变大是为了让数组的每个元素都对齐。

## ✅ 自测

1. 读汇编，写出等价的 C 函数并说明功能：
   ```asm
   # long g(long n)
   g:
       movl    $1, %eax          # i = 1
       movl    $0, %edx          # s = 0
   .L2:
       cmpq    %rdi, %rax
       jg      .L4
       addq    %rax, %rdx        # s += i
       addq    $1, %rax          # i++
       jmp     .L2
   .L4:
       movq    %rdx, %rax
       ret
   ```
2. `leaq 8(%rdi,%rsi,4), %rax` 计算的是什么？若 `%rdi` 是 `int *A`、`%rsi` 是 `long i`，它对应哪句 C？
3. `struct S { char c; int i; double d; };` 的 `sizeof` 是多少？三个成员偏移各是多少？
4. `double h(int a, double b, int c)`：三个参数在哪几个寄存器？返回值在哪？
5. `echo` 的帧是 `subq $24, %rsp`、`char buf[8]`，要覆盖返回地址至少需要多少个字符？若开了 canary，攻击者还差什么信息？

<details>
<summary>参考答案</summary>

1. `long g(long n) { long s = 0; for (long i = 1; i <= n; i++) s += i; return s; }`，即 1+2+…+n；`n <= 0` 时返回 0。注意 `movl $1,%eax` 会把 `%rax` 高 32 位清零，所以 `i` 是干净的 64 位值。
2. 计算 `A + 4*i + 8`（`%rsi` 是下标，比例因子 4），对应 `&A[i+2]`（或 `A + i + 2` 的地址）。
3. `sizeof = 16`：`c@0`，填充 1–3，`i@4..7`，`d@8..15`（`double` 要 8 对齐，正好紧接在 `i` 之后）；总大小 16 是最大对齐 8 的倍数。
4. `a→%edi`、`b→%xmm0`、`c→%esi`；返回值在 `%xmm0`。
5. **24 个**字符（8 字节 `buf` + 16 字节填充后才到返回地址）。开了 canary 还需先**泄露 canary 的值**（或绕过检查），否则写超会被 `__stack_chk_fail` 直接终止。

</details>
